### A.6 Recommendation (OSI license + OIDC + remote MCP over OAuth + OTel + Helm)

**LibreChat** is the only candidate meeting all five on primary sources: MIT; Keycloak OIDC; streamable-http MCP with PRM/DCR/PKCE/RFC 8707 OAuth (per-user tokens, identity headers); OTLP tracing (backend-level); official OCI Helm chart.
Caveats to plan around: (1) no MCP elicitation yet (PRs #8684 closed, #15550 open); (2) SDK 1.32.1 → protocol 2025-11-25, no CIMD (issue #17666 open); (3) OTel covers server/DB/Redis/HTTP, not GenAI spans; (4) latest tagged stable is v0.8.8 (v0.8.9 is RC).
Runner-up: **chat-ui** (Apache-2.0, SDK v2 with 2026-07-28 negotiation, full OAuth incl. CIMD, elicitation) but no OTel and only an in-repo chart. **Open WebUI** is functionally strongest on MCP (elicitation, DCR/static, session-token passthrough) but fails the OSI requirement (branding clause, self-described non-OSI). **Onyx** is MIT core with excellent MCP OAuth but its ee/ split and (unverified here) OTel/Helm were not checked in depth.

### B.1 pydantic/pydantic-ai
- License: **MIT** ("Copyright (c) Pydantic Services Inc. 2024 to present") — https://raw.githubusercontent.com/pydantic/pydantic-ai/main/LICENSE
- MCP client: `MCPToolset` accepts URL (Streamable HTTP recommended; `/sse` URLs → deprecated SSE), script path/`StdioTransport`, FastMCP transport, prebuilt `fastmcp.Client`, in-process server. `auth=` bearer string, `httpx.Auth`/`httpx2.Auth`, or literal `'oauth'` ("FastMCP's OAuth flow"); `headers=` static; `auth`/`headers` may be a function of run context ("each run gets its own session" → per-user). `elicitation_handler=` ("To enable elicitation, provide an `elicitation_handler`"), `sampling_model`, `.prefixed(...)`. Supports **FastMCP 3 (MCP SDK v1) and FastMCP 4 (MCP SDK v2)**; "FastMCP 4's modern protocol mode lacks sampling and elicitation, which need its legacy mode". Spec refs: 2025-11-25 tasks, 2025-06-18 elicitation. — https://pydantic.dev/docs/ai/mcp/client/
- OTel: "Pydantic AI emits OpenTelemetry data ... without using Logfire at all"; `Agent.instrument_all()` / `InstrumentationSettings(version=5 default; 6 opt-in; include_content, include_binary_content, tracer_provider)`; follows **OpenTelemetry GenAI semantic conventions "specifically version 1.37.0"**; plain OTLP via `OTEL_EXPORTER_OTLP_ENDPOINT`. — https://pydantic.dev/docs/ai/integrations/logfire/
- Providers via gateway: Anthropic — `AnthropicProvider(anthropic_client=AsyncAnthropic(base_url=..., api_key=...))` (documented for "Anthropic-compatible gateways and proxies"); OpenAI — `OpenAIProvider(base_url=..., api_key=...)` / `openai_client=`. — https://pydantic.dev/docs/ai/models/anthropic/ ; https://pydantic.dev/docs/ai/models/openai/

### B.6 openai/openai-agents-python
- License: **MIT** ("Copyright (c) 2025 OpenAI") — https://raw.githubusercontent.com/openai/openai-agents-python/main/LICENSE
- MCP: `MCPServerStreamableHttp`, `MCPServerSse` (deprecated transport), `MCPServerStdio`, `HostedMCPTool`; static headers; `params["auth"]` = `httpx.Auth` (SDK v1) / `httpx2.Auth` (v2); dependency `mcp>=1.19.0,<3`; with SDK v2 sends `server/discover` then falls back to `initialize`; **no built-in OAuth flow documented**; elicitation not mentioned. — https://openai.github.io/openai-agents-python/mcp/
- Tracing: exports to OpenAI backend by default; `add_trace_processor`/`set_trace_processors`; 31 third-party processors; **no native OTel/OTLP exporter documented**. — https://openai.github.io/openai-agents-python/tracing/

### B.7 Recommendation
**pydantic-ai** — MIT; Streamable HTTP MCP with bearer/`httpx.Auth`/OAuth and per-run (per-user) auth callables; elicitation + sampling; MCP SDK v1 and v2 via FastMCP 3/4 (so 2026-07-28 reachable, with the documented caveat that v2 "modern" mode drops sampling/elicitation); explicitly versioned GenAI semconv (1.37.0) with plain OTLP export; first-class Anthropic and OpenAI providers pointing at a custom gateway base URL.
Close second: **Microsoft Agent Framework** (MIT, SDK v2 only, GenAI semconv, `_meta` trace propagation to MCP servers). **Strands** if you need built-in OAuth client_credentials. ADK is solid but Google-oriented; LangGraph's MCP layer is beta and OTel goes through LangSmith; OpenAI Agents lacks native OTLP.
