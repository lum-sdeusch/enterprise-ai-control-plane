# Open-source AI/LLM gateways and LLM observability platforms — landscape as of 2026-11-06

Scope: components for an enterprise reference architecture that must be built entirely from free, open-source software. Every license, version and gating claim below was checked against a primary source (LICENSE file, README, official docs, GitHub page, vendor pricing page) during this research session; repository metadata (stars, latest release, last commit, commit activity) comes from shields.io badge JSON over the GitHub API. Items that could not be verified are flagged as such and collected in the final section.

Conventions: "OSS" = usable under the project's open-source license without a license key. "EE" = requires an enterprise/commercial license. SPDX identifiers are taken from the LICENSE file text, not from memory.

### A.2 LiteLLM proxy (BerriAI/litellm)

- License: `LICENSE` is MIT with a carve-out: "All content that resides under the 'enterprise/' directory of this repository, if that directory exists, is licensed under the license defined in 'enterprise/LICENSE'" (https://raw.githubusercontent.com/BerriAI/litellm/main/LICENSE). `enterprise/LICENSE.md` (BerriAI Enterprise License): software "may only be used in production, if you ... have agreed to" the Enterprise Terms and hold "a valid BerriAI Enterprise license for the correct number of user seats"; dev/test use allowed without subscription (https://raw.githubusercontent.com/BerriAI/litellm/main/enterprise/LICENSE.md). GitHub cannot auto-identify the license because of the split.
- Language: Python. Maturity: v1.108.1 released 2026-11-05; 63k stars; ~2.2k commits/month (shields.io). Company-governed.
- Enterprise gating (https://docs.litellm.ai/docs/enterprise): OSS includes virtual keys, budgets and rate limits, spend tracking, Admin UI, load balancing, MCP gateway, guardrails framework incl. custom guardrails and Presidio PII masking. License key (`LITELLM_LICENSE`) enables: SSO for Admin UI (free for up to 5 users from v1.76.0 — https://docs.litellm.ai/docs/proxy/admin_ui_sso), JWT-based auth ("JWT-based Auth requires a LiteLLM Enterprise license" — https://docs.litellm.ai/docs/proxy/token_auth), audit logs ("This feature requires a LiteLLM Enterprise license" — https://docs.litellm.ai/docs/proxy/audit_logs), RBAC, public/private routes, IP ACLs, key rotation, secret managers, multi-tenant org/projects, tag-based budgets, model-specific budgets per key, temporary budget increases, soft-budget email alerts, spend reports, team-based logging / disable logging per team, log export to GCS/Azure Blob, guardrails per key/team, enforced required params, SCIM, custom branding, max request/response size, plus specific guardrails (`llmguard_moderations`, `llamaguard_moderations`, `hide_secrets`, `openai_moderations`, `google_text_moderation`, `lakera_prompt_injection`, `aporia_prompt_injection`).
- Prometheus: the current Prometheus page carries no Enterprise callout for the core `prometheus` callback; only "Managed Batch Metrics" are marked "Enterprise only" (https://docs.litellm.ai/docs/proxy/prometheus). Metrics include spend, tokens, latency, budgets remaining per team/key/user/org/end_user, rate-limit remaining, deployment health, cache hits, guardrail latency, MCP tool spend; labels include `team`, `user`, `end_user`, `model`, `api_provider`. No `gen_ai.*` labels.
- Providers: 100+ (OpenAI, Anthropic, Bedrock, Vertex, Azure, vLLM, Ollama) per the docs provider index (https://docs.litellm.ai/docs/providers; not re-verified item by item in this pass).
- Routing: router with fallbacks, retries, load-balancing strategies and model groups (https://docs.litellm.ai/docs/routing; Enterprise page confirms load balancing is OSS).
- Cost tracking / budgets: per key, team, user, org, end_user; spend logged to Postgres (OSS). Tag/model-specific budgets EE.
- Token-based rate limiting: tpm/rpm per key/team/user (OSS; Prometheus exposes remaining tokens per key and model).
- Semantic caching: `redis-semantic`, `valkey-semantic`, `qdrant-semantic` (plus redis, s3, gcs, local, disk). Docs warn semantic caching "suits single-shot prompts and goes badly wrong on agentic traffic" (https://docs.litellm.ai/docs/proxy/caching). Cache controls: per-request `cache: {ttl, s-maxage, no-cache, no-store, namespace}`; per-virtual-key cache settings in key metadata (ttl, s-maxage, no-cache, no-store). No documented per-user/tenant isolation of cache entries; `namespace` is described only as a storage namespace (https://docs.litellm.ai/docs/proxy/caching_controls).
- Guardrails: modes `pre_call`, `during_call`, `post_call`, `logging_only`; integrations: Presidio, Lakera, Aporia, Bedrock Guardrails, Azure Content Safety, OpenAI Moderation, Guardrails AI, Model Armor, Pangea, Javelin, Lasso, generic Guardrail API, custom code (`apply_guardrail`). EE: per-key guardrails, tag-based modes, model-level guardrails, dynamic params (https://docs.litellm.ai/docs/proxy/guardrails/quick_start).
- Authentication: master key + virtual keys (OSS); JWT/OIDC claim mapping (`team_id_jwt_field`, `user_id_jwt_field`, `end_user_id_jwt_field`, `org_id_jwt_field`) is EE; mapped identities flow into spend tracking and logs.
- OpenTelemetry: `otel` callback with OTLP http/grpc; "Names follow OTEL GenAI semconv"; `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental` adds `gen_ai.provider.name` and changes span name/kind; content controlled by `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` (`NO_CONTENT`/`SPAN_ONLY`/`EVENT_ONLY`/`SPAN_AND_EVENT`), per-handler `capture_message_content`; `litellm.turn_off_message_logging=True` forces `NO_CONTENT` (https://docs.litellm.ai/docs/observability/opentelemetry_integration).
- Kubernetes: two official OCI Helm charts (`oci://ghcr.io/berriai/litellm-helm` monolithic; `oci://ghcr.io/berriai/litellm/chart/litellm` microservices, >=1.89.0), raw manifests, Terraform modules; Postgres required, Redis for multi-replica (https://docs.litellm.ai/docs/proxy/deploy). No CRDs / Gateway API.

### A.4 Agent Router, formerly Envoy AI Gateway (theagentrouter/agent-router; old envoyproxy/ai-gateway redirects)

- License: Apache-2.0 (https://raw.githubusercontent.com/envoyproxy/ai-gateway/main/LICENSE; README: "same Apache 2.0 license"). Language: Go (Go module path unchanged per README).
- Rename/governance: "On 10 September, Agent Router, previously Envoy AI Gateway, officially joins the Agentic AI Foundation"; blog dated 2026-09-09; CRDs/API group `aigateway.envoyproxy.io`, `aigw` CLI, namespace, images, Helm charts unchanged; repo moved to `theagentrouter/agent-router` (https://theagentrouter.ai/blog/envoy-ai-gateway-is-now-agent-router; https://raw.githubusercontent.com/envoyproxy/ai-gateway/main/README.md). Footer: "Agent Router a Series of LF Projects, LLC".
- Maturity: v1.0.x first GA 2026-06-23 (declared core v1beta1 API stable, 16 providers, MCP gateway); v1.1.x added token counting, OTel GenAI tracing; v1.2.x 2026-10-06 (MCP security hardening, Envoy Gateway v1.9) (https://theagentrouter.ai/release-notes/). 2.4k stars; 44 commits/month.
- Providers (https://theagentrouter.ai/docs/capabilities/llm-integrations/supported-providers): OpenAI, Anthropic (native Messages endpoint), AWS Bedrock, Azure OpenAI, Gemini (OpenAI-compatible endpoint), Vertex AI (ADC/SA key/Workload Identity Federation), Anthropic on Vertex, Mistral, Groq, DeepSeek, many OpenAI-compatible providers; self-hosted vLLM marked ⚠️ (depends on schema; vLLM uses OpenAI format); Ollama not listed.
- Routing: model name virtualization, provider fallback, InferencePool (Gateway API Inference Extension) for self-hosted models, header/body mutations (https://theagentrouter.ai/docs/capabilities/). Retries not documented on the capabilities page.
- Cost/rate limiting: token-aware rate limiting via Envoy Gateway `BackendTrafficPolicy` with `llmRequestCosts` (input/output/total/cached tokens, CEL-weighted); tenants keyed by header (`x-tenant-id`, `Distinct`); per-tenant limits via `limit.fromMetadata` from ext_authz; Redis required; "Token usage is charged after the response completes" (https://theagentrouter.ai/docs/capabilities/traffic/usage-based-ratelimiting). `QuotaPolicy` (`aigateway.envoyproxy.io/v1alpha1`) caps tokens per model per backend over 1s/1m/1h/1d windows with header-based bucket rules and shadow mode (https://theagentrouter.ai/docs/capabilities/traffic/quota-policy). No dollar budgets or per-key spend ledger.
- Semantic caching: none documented (only provider-agnostic prompt caching passthrough via `cache_control`).
- Guardrails: no first-party guardrail page; processing happens in the Envoy ext_proc ("ExtProc plays a central role") and Envoy Gateway ext_authz/extension policies can be attached (https://theagentrouter.ai/docs/concepts/architecture/data-plane).
- Authentication: Envoy Gateway `SecurityPolicy` — JWT validation, JWT claim-based authorization, OIDC, API key, basic auth, mTLS, external authorization, IP allow/deny (https://theagentrouter.ai/docs/capabilities/security/). Upstream auth: API key, AWS, Azure, GCP credentials (`BackendSecurityPolicy`).
- OpenTelemetry (https://theagentrouter.ai/docs/capabilities/observability/tracing): enable with `OTEL_EXPORTER_OTLP_ENDPOINT`; default convention OpenInference; `AI_GATEWAY_TRACING_SEMCONV=gen_ai` emits `gen_ai.*` (span `chat {model}`, kind CLIENT); content opt-in via `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true`; OpenInference hiding via `OPENINFERENCE_HIDE_INPUTS/OUTPUTS/...`; MCP spans; header→attribute mapping (`agent-session-id:session.id`); GenAI metrics page.
- Kubernetes: Helm `oci://docker.io/envoyproxy/ai-gateway-crds-helm` + `oci://docker.io/envoyproxy/ai-gateway-helm` v1.2.0; CRDs AIGatewayRoute, AIServiceBackend, BackendSecurityPolicy, QuotaPolicy, GatewayConfig; standalone `aigw run` (https://theagentrouter.ai/docs/getting-started/installation; https://theagentrouter.ai/docs/concepts/resources).

## OpenTelemetry GenAI semantic conventions — status (verified 2026-11-06)

- The GenAI conventions moved out of `open-telemetry/semantic-conventions` into `open-telemetry/semantic-conventions-genai` (opentelemetry.io pages now show "Moved" notices; 524 stars; no tagged releases yet; main semconv repo at v1.45.0, 2026-11-02). Docs: `docs/gen-ai/README.md` — "Status: Development" — linking client-inference, client-embeddings, execute-tool, retrieval, client-invoke-agent, events, exceptions, metrics, token metrics, model spans, realtime, agent spans; provider pages Anthropic, Azure AI Inference, AWS Bedrock, OpenAI; plus `a2a.md` and `mcp.md`.
- Client inference spans (Development): name `{gen_ai.operation.name} {gen_ai.request.model}`, kind CLIENT (INTERNAL for in-process); Required `gen_ai.operation.name`, `gen_ai.provider.name`; Conditionally Required `gen_ai.request.model`, `gen_ai.conversation.id`; Recommended `gen_ai.response.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`; Opt-In `gen_ai.input.messages`, `gen_ai.output.messages`, `gen_ai.system_instructions`, `gen_ai.tool.definitions` ("likely to contain sensitive information including user/PII data"), with `_ref` variants for external storage. Model spans doc: "Model instructions, user messages, and model outputs are considered sensitive… OpenTelemetry instrumentations SHOULD NOT capture them by default, but SHOULD provide an option for users to opt in."
- Agent spans (Development): `create_agent {gen_ai.agent.name}` (CLIENT), `invoke_agent` (INTERNAL), `gen_ai.agent.id/name`. Execute tool: `execute_tool {gen_ai.tool.name}` (INTERNAL); `gen_ai.tool.name` Required, `gen_ai.tool.call.id` Conditionally Required, `gen_ai.tool.type`/`description` Recommended, `gen_ai.tool.call.arguments`/`result` Opt-In.

- Content-capture control in instrumentations (opentelemetry-instrumentation-openai-v2 2.4b0, 2026-05-01): `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` — off by default; `true` (legacy events), `span_only`, `event_only`, `span_and_event` (the latter three only with `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental`; without the opt-in the instrumentation follows semconv v1.30.0) (https://pypi.org/project/opentelemetry-instrumentation-openai-v2/). ## OpenTelemetry Collector processors for redaction (contrib v0.164.1, Oct 2026)

- redaction processor: stability traces beta, metrics alpha, logs alpha; `allowed_keys` (fail-closed allow-list), `blocked_values`/`allowed_values` regexes (mask matching parts), `blocked_key_patterns`, `ignored_keys`/`ignored_key_patterns`, `hash_function` (md5, sha1, sha3, hmac-sha256, hmac-sha512; HMAC recommended for low-entropy values); applies to span attributes, log attributes and map bodies, metric datapoint attributes; span events not documented (https://raw.githubusercontent.com/open-telemetry/opentelemetry-collector-contrib/main/processor/redactionprocessor/README.md).
- transform processor (OTTL): beta for traces/metrics/logs (profiles development); `replace_pattern`, `replace_all_patterns`, `delete_key`, `truncate_all`, `spanevent` context; default `error_mode: ignore` means a failed statement logs and passes data through unchanged — set `propagate` for fail-closed redaction (https://raw.githubusercontent.com/open-telemetry/opentelemetry-collector-contrib/main/processor/transformprocessor/README.md).
- attributes processor: beta for traces/metrics/logs; insert/update/upsert/delete/hash/extract/convert; documented as superseded by the transform processor (https://raw.githubusercontent.com/open-telemetry/opentelemetry-collector-contrib/main/processor/attributesprocessor/README.md).

## Recommendations for a strictly open-source enterprise stack

Part A (gateway):
1. agentgateway (Apache-2.0, LF/AAIF): no enterprise gating found; Gateway-API-native CRDs; JWT/JWKS + API keys + CEL RBAC; token budgets keyed by key/tenant/JWT claim; failover priority groups and virtual models; regex/webhook/Bedrock/Model Armor guardrails with tool-input/output scope; GenAI-semconv LLM and MCP spans; Inference Extension support. Gaps: no semantic cache; budgets in tokens not USD; prompt-content capture in spans undocumented.
2. Agent Router (ex-Envoy AI Gateway; Apache-2.0, AAIF, GA since June 2026): Envoy Gateway SecurityPolicy (JWT/OIDC/API key/mTLS), QuotaPolicy + token-aware rate limiting, model virtualization, provider fallback, `gen_ai.*` tracing with explicit content opt-in, InferencePool. Gaps: no built-in guardrails or semantic cache (ext_proc hooks only), header-based tenancy.
- Non-K8s alternatives: LiteLLM (MIT; JWT auth, audit logs, per-key guardrails, SSO >5 users are EE) or Bifrost (Apache-2.0; USD budgets and OTel OSS, but guardrails/OIDC/RBAC/audit logs EE). APISIX if an ASF-governed gateway with per-consumer token limits and semantic cache suffices (no cost ledger, no GenAI tracing).
- Knocked out: Kong (AI advanced plugins EE; OSS frozen at 3.9), Traefik Hub (commercial), TensorZero (archived), Helicone/ai-gateway (GPL-3 LICENSE vs Apache README, dormant), Portkey (acquired, repo idle since May 2026, budgets/semantic cache hosted/EE), LLMGateway (AGPL + ee/), Lunary (not OSS).

Part B (observability):
1. Langfuse OSS (MIT core): OTLP + `gen_ai.*`/OpenInference mapping, tool spans, sessions, cost, free SSO/OIDC and org RBAC, Helm. Accept that retention policies, audit logs, project-level RBAC and server-side masking are EE — mitigate with collector redaction, SDK masking, API deletion jobs, and K8s/IdP-level audit.
2. Opik (Apache-2.0): rich tracing/eval UI, OTLP/HTTP with `gen_ai.*` and thread grouping, Helm; must be fronted by an OIDC proxy because OSS has no user management. OpenLIT (Apache-2.0, OTLP gRPC/HTTP, native `gen_ai.*`, cost/MCP views) is the OTel-purist alternative; SigNoz if a general APM is wanted (MIT core, but its collector is AGPL-3.0 and OIDC/SAML SSO and RBAC are EE).
- Knocked out: Phoenix (ELv2, non-OSI), Lunary (closed), Traceloop platform (SaaS), Tempo (AGPL-3.0, no GenAI UX), Helicone (no OTLP ingestion, stale releases).
